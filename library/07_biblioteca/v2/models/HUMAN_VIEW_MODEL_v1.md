# HUMAN_VIEW_MODEL_v1

Version: 1.0.0

## Navigation contract

`LANGUAGE → PURPOSE / PROCESS → ENTITY → DOCUMENT`

## Rules

- `MULTIPROCESS_DOCUMENT = MANY_HUMAN_POINTERS_ALLOWED`
- `SOURCE_BINARY_DUPLICATION = NO_BY_DEFAULT`
- Human folder placement is a view, not documentary identity.
- A rename or move of a human pointer does not change `LIB_FILE_ID`.
- A source document may appear in several human views through shortcuts/pointers when supported and authorized.
- Mass shortcut creation is not authorized in this phase.

## Language

Primary navigation uses `PRIMARY_LANGUAGE`.
Documents with relevant secondary languages may receive additional human pointers without creating a new binary.

## Purpose / Process

Human-purpose paths are generated from controlled `PROCESS` values. Multi-process documents may map to multiple process views.

## Entity

`ENTITY` is a navigation reference, not a new identity layer. It should point to a catalogued entity such as institution, source family, standard, taxon or other named subject appropriate to the document.

## Existing V1 folders

V1 physical folders are preserved as historical/source locations. V2 does not require immediate migration to the new human view.
