# 00000 · JBLR · Restore Protocol v1

Status: `MANDATORY_FOR_00000`
Date: 2026-08-26

## Rule 0

`NO_STRATEGIC_WORK_BEFORE_RESTORATION = TRUE`

A new continuity of `00000` must restore, in order:

1. North Star.
2. Control Tower current state.
3. Resource/tool registry.
4. Strategic decisions and roadmap.
5. Volatile reality in GitHub/Neon/Drive/Event Bus where relevant.

`PERSISTED_EVIDENCE > CONVERSATIONAL_MEMORY`

`GITHUB_REALITY > STALE_EVENTBUS_STATE` when GitHub contains later concrete reproducible evidence.

## Required restoration answers

Before strategic work `00000` must know:

- FINAL_OBJECTIVE
- CURRENT_PROGRAM
- CURRENT_MACRO_PHASE
- CURRENT_WORKSTREAM
- CURRENT_STEP
- NEXT_STEP
- BLOCKERS
- ACTIVE_PROJECTS
- CRITICAL_RESOURCES
- CORRECT_TOOL_FOR_THE_NEXT_ACTION
- LAST_PERSISTED_CHECKPOINT

If any material item is unresolved, restoration is `FAIL` until evidence is recovered or the unknown state is explicitly registered.

## Work packet checkpoint

Each significant work packet records:

- objective served;
- inputs;
- resources/tools used;
- changes made;
- output evidence;
- prior state;
- resulting state;
- downstream effects;
- next step;
- blockers.

Update control state whenever a work packet closes, project/phase changes, release is frozen, delivery is accepted/rejected, a structural resource is created, a strategic decision changes, or a Direction General chat is closed.

## Anti-drift gate

Before accepting a new workstream `00000` must map it to the North Star and identify affected Types, Fields, Relations, Processes or infrastructure. Work that cannot be mapped is classified before it can displace the main roadmap.
